## Generate Image (GPT Image 2)
`POST https://api.snapgen.ai/uapi/v1/imagen/gpt-image-2`

This endpoint generates images using the GPT Image 2 model. It supports prompt-based text-to-image generation, optional reference images for image-to-image editing, and configurable quality modes and resolutions.

---

## Example Request
::code-group

```bash [terminal]
curl -X POST https://api.snapgen.ai/uapi/v1/imagen/gpt-image-2 \
  -H "x-api-key: <your api key>" \
  -H "Content-Type: multipart/form-data" \
  --form "prompt=A photorealistic portrait of an astronaut riding a horse on Mars" \
  --form "aspect_ratio=16:9" \
  --form "mode=medium" \
  --form "resolution=4K" \
  --form "ref_history=<history_uuid>" \
  --form "files=@reference.png"
````

```python [py]
import requests

url = "https://api.snapgen.ai/uapi/v1/imagen/gpt-image-2"
headers = {
    "x-api-key": "<your api key>"
}

    "resolution": "4K",

response = requests.post(url, headers=headers, data=data, files=files)

```

## Request Parameters

`prompt` [string] *required*
The text prompt describing the image you want to generate. Be as descriptive as possible for the best results.

---

`mode` [string]
Quality mode for generation. Higher modes produce better quality but cost more credits.

* `low` (default) — Fast generation, lower cost
* `medium` — Balanced quality and speed
* `high` — Highest quality output

---

`aspect_ratio` [string]
Image aspect ratio:

* `1:1` (default) — Square
* `16:9` — Widescreen landscape
* `9:16` — Portrait (vertical)
* `4:3` — Standard landscape
* `3:4` — Standard portrait
* `21:9` — Ultra-wide
* `3:2` — Classic landscape
* `2:3` — Classic portrait

---

`resolution` [string]
Output image resolution:

* `1K`
* `2K` (default)
* `4K`
* `8K`
* `10K`
* `12K`

---

`ref_history` [string]
UUID of a previously generated image. The system will use that image as a reference for image-to-image generation.

---

`files` [array\<File\>]
Optional uploaded reference images used as subjects for image-to-image generation.

Supported formats:

* `.png`
* `.jpg`
* `.jpeg`
* `.webp`

---

## How Reference Images Work

You can provide reference images in two ways:

### 1. From History (`ref_history`)

* Uses a previously generated image as reference
* Must belong to the current user
* Must be of type `image`

---

### 2. Upload Files (`files`)

* Local images sent via multipart form
* Used as subject/style reference for editing

## Response Fields

`id`
Unique identifier of the request

`uuid`
Unique identifier for tracking generation

`user_id`
ID of the user making the request

`model_name`
AI model used (`gpt-image-2`)

`input_text`
Original prompt

`generate_result`
URL to generated image (available after completion)

`status`
Current processing status

`status_desc`
Human-readable status

`estimated_credit`
Estimated credits to be deducted upon completion

`media_type`
Type of generated media (`image`)

`created_at`
Timestamp of request creation

---

## Status Codes

* `1` - Processing
* `2` - Completed
* `3` - Failed

## Best Practices

1. **Write detailed prompts**
   → More detail = higher quality output

2. **Choose the right mode**
   → Use `low` for quick drafts, `high` for final production images

3. **Use appropriate resolution**
   → Match resolution to your output needs (e.g., `2K` for web, `4K`+ for print)

4. **Leverage reference images**
   → Provides style and content guidance for better consistency

5. **Start with lower settings**
   → Test with `low` mode and `2K` resolution before scaling up
